VODHit beta tester guide

Everything you need to install, explore, and safely test the macOS beta. Read the limitations before interpreting the analytics. This guide describes intended capabilities verified in the current codebase; installer availability and complete release acceptance are separate checks.

Before you begin

The first public-facing installer is not yet released. Follow installation steps only after receiving a signed and notarized DMG through an official beta invitation. You do not need to grant access to your Google account, disable Gatekeeper, or install Node.js.

1. What VODHit does

VODHit is a local-first workspace for exploring exported YouTube Studio data and recording production decisions. The beta supports dashboards, sortable video tables, rankings, time-period comparisons, charts, video notes, Markdown checklists, custom video attributes, group comparisons, locally recorded change history, and backup/restore.

CSV-only: the application does not connect to Google OAuth, YouTube Data API or Analytics API. It does not automatically fetch new analytics, thumbnails, video status or metadata. Imported data reflects the export date and report coverage, not the current state of YouTube.

Each local beta profile is tied to one YouTube channel. Multiple-channel switching, cloud synchronization, account-based sync, payments and automatic app updates are not included.

2. Requirements and safe setup

  • Mac with Apple Silicon (M1/M2/M3/M4 or newer compatible M-series), macOS 12 or later. Intel Macs are not verified.
  • Enough free local storage for your exports, notes and backup copies.
  • Your own YouTube Studio exports in CSV, TSV or ZIP format.
  • A separate folder for VODHit data. Avoid choosing the folder used by another analytics app.

Privacy: VODHit stores imports, notes and settings on your Mac. It does not upload these files to a VODHit cloud service. If you select a folder synchronized by iCloud, Dropbox or another provider, that provider may transfer those files independently.

Never share API tokens, YouTube account credentials or unredacted private analytics with beta support. Start with a small or synthetic export if you prefer to test without real channel figures.

3. Install and first launch

  1. Use only the official download instructions supplied with your beta invitation. Confirm the version and, when provided, the SHA-256 checksum.
  2. Double-click the downloaded .dmg file. Drag the application to Applications in the Finder window.
  3. Eject the mounted disk image. Start the app from Applications. You should not need Terminal, Node.js or a separate server.
  4. At first launch, choose Use recommended folder or Choose another folder. The recommended directory currently points to ~/Library/Application Support/ShotKot Beta/. The custom-folder option creates a VODHit Data subfolder inside the parent you choose.
  5. Do not select an existing unrelated application's folder or the root of a drive. Keep the chosen profile directory available and writable.
  6. Open the data settings and verify the full active directory path. Use the Show data folder in Finder control to confirm it is correct.

Early builds may still display the technical name ShotKot Beta until the VODHit branding change is included in a verified release. Follow the release notes shipped with your specific build.

Important: the beta remembers one profile and should not create a new empty profile if the saved folder is missing, the disk is disconnected, or the profile ID is different. If you see a recovery warning, reconnect the original disk or locate the original profile. Do not create a replacement folder to work around the message.

4. Export useful data from YouTube Studio

  1. Open YouTube Studio, then Analytics → Advanced mode (in Polish: Statystyki → Tryb zaawansowany).
  2. View the channel rather than an individual video. Select the Content / Treść breakdown and an explicit date range, e.g. Last 365 days.
  3. Set the date granularity to Daily / Dziennie. Selecting 365 days alone does not guarantee daily records; avoid weekly, monthly or yearly grouping.
  4. Include identifiers such as Content/video ID and Video title. If available, include publication date and duration.
  5. Include five base metrics: Views, Watch time (hours), Average view duration, Thumbnail impressions, and Thumbnail click-through rate (CTR %).
  6. Select Export current view and download CSV or ZIP. Do not edit numerical values or column headers before importing.

File names and localized column names can vary. Some metrics may be unavailable for some videos: missing is not zero. YouTube's exported tables may also have a 500-row limit; check whether the export covers all intended videos and dates.

Official reference: YouTube Studio advanced analytics exports.

5. Import and assign your channel

  1. In VODHit, open Data settings → Studio imports (Polish UI: Ustawienia danych → Importy Studio).
  2. Choose Add Studio CSV/TSV/ZIP (Polish UI: Dograj CSV/TSV/ZIP ze Studio) and select your export.
  3. Review the import preview: video count, date range, detected daily dates, available metrics, and all warnings. The preview cannot conclusively prove that the report used Daily grouping; verify that in Studio yourself.
  4. On the first import, enter a recognizable channel name and confirm that the files belong to that channel. If the export explicitly contains a valid YouTube Channel ID, the app can record it for later comparison.
  5. If the file has no reliable Channel ID, you may be asked to reconfirm its channel at future imports. Never import another channel into the same profile.
  6. Complete the import only when the preview and channel identity look correct. After import, check the selected date period and the displayed video table.

Do not confuse import success with complete data. Partial records may be stored, but existing calculations can exclude videos without all five base metrics. Apparent totals and rankings may represent only a subset of the channel.

Explicit zero and unavailable values are different. If an analytics field is missing, do not interpret it as zero. Do not use current beta rankings as an authoritative source for channel-wide totals or financial decisions.

6. Explore the workspace

After import, explore the dashboard, video table, rankings and chart views. Try sorting videos, narrowing the date range, and comparing different periods. The visualizations use locally imported snapshots; they are not live YouTube measurements.

7. Notes, checklists and video attributes

  1. Open a video and create or edit its local note. The editor supports Markdown-style notes and checklists.
  2. Create a simple test note such as Beta test: thumbnail changed, add a checklist item, and save.
  3. Use custom flags/attributes to describe production characteristics or experiments. These are your own annotations, not facts retrieved from YouTube.
  4. Close and reopen the note; then quit and restart the app. Confirm that the note and custom metadata remain intact.

Saved notes live in your selected local data profile. Treat important notes like any other files: maintain backups, especially before updates or restoration.

8. Back up and restore safely

Use the Export backup action in the application's data settings to save a backup JSON file somewhere you control. Keep a copy outside the active profile folder (ideally on another drive). The file is not encrypted; store it securely.

  1. Export a backup and confirm that the file exists in Finder.
  2. If you want to test restore, first work in a disposable synthetic profile and create a separate backup of its initial state.
  3. Use Import/Restore backup only when you intend to replace the current managed profile data. Read the confirmation carefully.
  4. After restore, check notes, flags, channel identity and imported records. Reopen the app to verify persistence.

Restoring is not merging. It replaces managed profile data after validation; the app normally creates a pre-import recovery backup first. A backup from another populated profile is rejected. Do not use restore to combine channels or to migrate private data from a different application.

9. Known limitations and safety notes

  • Experimental analytics: several data-quality issues remain under development, including aggregation coverage, CTR sorting and some video status-dependent analyses. Do not use current output to make financial or other high-stakes decisions.
  • Manual imports only: no Google login, OAuth, API syncing, automatic metadata retrieval or live thumbnail updates.
  • Single-channel profile: do not mix two channels into one profile. Switching channels is not a supported beta feature.
  • Missing data: videos with incomplete metrics can remain stored while being omitted from some calculations. Blank does not equal zero.
  • Local storage: no VODHit cloud backup or encryption of exported backup JSON; an external sync service may independently upload a selected folder.
  • No automatic updater: new builds must be downloaded and installed manually; keep a separate backup before updating.
  • Platform scope: Apple Silicon is the verified build target. Intel and older macOS versions are unsupported or unverified.
  • First-run edge cases: several native GUI recovery scenarios (missing volume, bad permissions or profile mismatch) still need confirmation on a clean test account or VM.

10. Suggested tester checklist

Please spend approximately one session checking the following flow, then report what actually happened. Skip any step that requires risking important data.

  1. Download the approved DMG; confirm you can install and start it normally without bypassing Gatekeeper.
  2. Choose a new local folder and check that the full path and Finder reveal agree.
  3. Import one correctly prepared Studio export; review any warnings and assign its channel.
  4. Check the date range, a few videos, missing metrics and sorting behavior.
  5. Create a note and checklist item, save and restart the app; verify persistence.
  6. Export a backup; verify that a JSON file was actually saved.
  7. Quit the app, reopen it, and confirm the same profile and data appear.
  8. Record bugs, confusing wording, unexpected numbers and missing features. Include each expected versus actual result.

Advanced testers may use a clean macOS account or VM to verify default-folder selection, cancelling onboarding, disconnected drives and recovery warnings. Never intentionally corrupt a real profile.

On macOS, press Shift + Command + 4 to capture a selected screen area. Redact private channel IDs, revenue, email addresses and file paths before sharing. Prefer synthetic sample exports if a reproducible input file is needed.

Report unexpectedly missing data, a different channel appearing, failed backup, or two windows editing one profile as a high-priority safety issue. Stop using the affected profile until it has been examined.

12. Troubleshooting, updates and removal

macOS refuses to open the app

Verify that the installer came from the official beta channel and that the release is signed and notarized. Do not disable Gatekeeper, use quarantine-removal commands or install an unsigned replacement; contact beta support with the exact warning.

The selected folder is unavailable

Reconnect the original volume or choose the same existing profile through the recovery prompt. Check disk permissions and free space. Do not create a blank replacement folder or delete the profile lock file.

Import rejected or numbers appear incomplete

Verify Studio's Daily grouping, channel scope, dates, required columns, and any missing metrics. A successful partial import can still result in incomplete rankings.

Updating the beta

Make an export backup, quit the old application using Command + Q, install the newer approved release, and open the same saved data profile. Do not run multiple app versions simultaneously against one profile.

Removing the beta

Quit the application and move the app from Applications to Trash. This should not remove the separate data profile or exported backups. Do not delete the profile directory unless you have deliberately decided to remove your local data.
